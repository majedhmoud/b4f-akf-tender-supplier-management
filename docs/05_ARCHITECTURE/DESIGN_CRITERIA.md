# Design Criteria (V1)

Status: accepted.

The qualities every design and code change is checked against. Each criterion names how we meet it and where the rule lives. For the Analysis and Design study, these are the non-functional requirements ([submission requirements](../01_PROBLEM/SUBMISSION_REQUIREMENTS.md)).

| Criterion | How we meet it | Rule |
|---|---|---|
| **Sealed, blind evaluation** | Legal → Technical → Financial, each seeing only the bids that passed the stage before. The `technical_committee` and `financial_committee` see a **bidder code**, never the supplier. Neither sees the other's offer. | [ADR 0002](ADR/0002_INDEPENDENT_TECHNICAL_AND_FINANCIAL_EVALUATION.md), [ERD](ERD.md#sealed-blind-evaluation-enforced-by-the-access-service) |
| **Least privilege** | Deny by default. One access service decides every tender, bid, and evaluation read. Records a user may not see return `404`. Committee access comes only from an approved **committee assignment**. | [Capability matrix](CAPABILITY_MATRIX.md), [standards §2.2](../04_RULES/ENGINEERING_STANDARDS.md#22-authorization) |
| **One view per audience** | A separate response DTO for each audience, never one trimmed by conditions. | [Standards §2.7](../04_RULES/ENGINEERING_STANDARDS.md#27-dtos), [class diagram](CLASS_DIAGRAM.md#access-service-and-response-views) |
| **Secure authentication** | bcrypt passwords, HttpOnly JWT cookies, CSRF tokens, refresh rotation with replay detection, single-use expiring account setup links, rate limits. | [Standards §2.1](../04_RULES/ENGINEERING_STANDARDS.md#21-authentication), [standards §2.4](../04_RULES/ENGINEERING_STANDARDS.md#24-rate-limiting), [API contract §1.1](API_CONTRACT.md#11-session-csrf-refresh) |
| **Safe files** | Private storage, random server-generated keys, type and size checks, short-lived signed downloads, neutral file names for blind reviewers. | [Standards §2.5](../04_RULES/ENGINEERING_STANDARDS.md#25-file-upload-security), [ERD](ERD.md#document-ownership), [ADR 0006](ADR/0006_LOCAL_DISK_FILE_STORAGE.md) |
| **Server-enforced rules and time** | Every permission, deadline, and status change is checked on the server, by server time. The UI only shows or hides controls. | [Standards §2.7](../04_RULES/ENGINEERING_STANDARDS.md#27-dtos), [API contract §1.1](API_CONTRACT.md#11-session-csrf-refresh) |
| **Controlled lifecycle** | A tender changes status only through the listed transitions. Jobs change it only from the expected status, so retries do nothing. | [WORKFLOWS.md](../01_PROBLEM/WORKFLOWS.md#tender-lifecycle), [ERD](ERD.md#lifecycle-jobs) |
| **Reliability** | Idempotency keys on critical actions. Revision checks on edits (`409 VERSION_CONFLICT`). One transaction for operations that must succeed or fail together. Retry-safe background jobs and email delivery. | [API contract §1.3](API_CONTRACT.md#13-idempotency), [API contract §1.4](API_CONTRACT.md#14-check-order), [standards §3.2](../04_RULES/ENGINEERING_STANDARDS.md#32-database-transactions), [ERD](ERD.md#emails), [standards §5](../04_RULES/ENGINEERING_STANDARDS.md#5-scalability-and-reliability) |
| **Auditability** | Every agreed workflow action is an audit event with actor, action, resource, and time. No passwords, tokens, or document contents in logs. | [Standards §8](../04_RULES/ENGINEERING_STANDARDS.md#8-audit-logging) |
| **Expandability** | A modular monolith: one module per business domain, talking only through public services. New areas, such as supplier ratings, are added without reworking existing ones. | [Standards §1.1](../04_RULES/ENGINEERING_STANDARDS.md#11-modular-monolith), [ERD](ERD.md#extension), [architecture](ARCHITECTURE.md) |
| **Bilingual by design** | English and Arabic interface with right-to-left layout. Tender content falls back to the other language. Emails use the recipient's language. | [ERD](ERD.md#language) |
| **Performance** | Paginated lists (20 by default, 100 at most), no N+1 queries, indexes for the deadline jobs and queues, short public caching for published tender lists, published tender details, and public reference data. | [Standards §4](../04_RULES/ENGINEERING_STANDARDS.md#4-performance), [API contract §1.2](API_CONTRACT.md#12-query-cache-and-http-caching) |
| **Usability and responsiveness** | Web screens work on desktop and phone widths (new, set here). Countdowns use server time. The mobile supplier companion covers browsing and following bids. | [V1 scope](../03_SCOPE/V1_SCOPE.md), [API contract §1.1](API_CONTRACT.md#11-session-csrf-refresh) |
| **Maintainability** | Shared glossary terms in code and docs, typed DTOs, a Swagger-generated client, tests for every capability matrix row and the sealed-bid acceptance check. | [Glossary](../GLOSSARY.md), [standards §9](../04_RULES/ENGINEERING_STANDARDS.md#9-testing), [ADR 0004](ADR/0004_TECHNOLOGY_STACK.md) |
